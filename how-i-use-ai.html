What AI does, what I decide

The split, plainly.

AI does
  • Drafts: a first pass at variants, dark-mode values, copy and code.
  • Reads the system through Figma MCP and keeps to the tokens it finds.
  • Maps components to code through Code Connect and writes the usage examples.
  • Critiques a screen in order (goal, flow, hierarchy, component, pixel) when I ask it to.
  • Writes the JavaScript on this site, and most of the CSS, from my brief.
I decide
  • What the problem is, and whether it is worth solving.
  • The palette, the type scale, the spacing rhythm, the names. The system is mine.
  • What ships. Every generated screen is reviewed against the tokens before it goes anywhere.
  • Every number. If AI writes a metric I cannot source, it comes out.
  • When to stop. AI will keep going; the taste call is the job.
02

Where it sits in the workflow

The same five steps as the pipeline.

01

Tokens

I set the colours, type, space and radius as Figma variables. AI proposes the dark-mode counterparts and checks contrast; I accept or adjust each pair.

02

Components

I define the anatomy, states and names. Claude generates the variant matrix through Figma MCP, bound to the variables, and lists every binding for me to check.

03

Code Connect

AI drafts the mapping from Figma properties to props. I verify it against the real component and fix what drifted.

04

Figma MCP

A prompt goes in, a component comes out in Figma and in code. The replay on the home page shows the loop; the audit prompt in the library is how I check the result.

05

Ship

Review, then publish. The library and the code stay in step because the same tokens drive both.

03

When AI got it wrong

Real examples from this site. Each caught by review, not by the model.

The logo's g went white in dark mode

Claude mapped the mark's ink to the theme token, so the g on the lamp cone inverted with the page. It looked broken, not clever. Fixed by pinning the g to ink and leaving the cone light.

A metric that did not exist

An early draft of the facts row claimed a 30% improvement. No source, so it was deleted. Everything on the site now is a count I can stand behind.

Career years filled in by guesswork

The career map needed one entry per year from 2018 to now. Claude placed the middle years from the resume's date ranges, which is a guess. Those placements are flagged and I am confirming them one by one.

A gallery view that rendered blank

The bento layout came back empty: the grid aligned items to the start and each tile collapsed to zero height. A one-line CSS fix, found by reading the computed styles, not by asking again.

A one-page resume that spilled to two

The print stylesheet let the sheet grow with its content. The page now has a fixed A4 height and hidden overflow, and the PDF is checked for a single page every time it is regenerated.

Text a screen reader would read as nonsense

The resume button exposed its progress counter, so it read as “Resume.pdf0%”. AI did not catch this; a review pass did. The counter is hidden from assistive tech now.

04

Rules I hold to

Short, so they get followed.

Draft, never decide

AI output is a starting point. It never ships without a human reading it.

Tokens or nothing

A generated component binds to the system's variables or it is rejected.

No real data in prompts

Case studies use sample data. The product's real content stays inside Zoho.

Say when it is AI

This page and the chat both say what is generated and what is not.
